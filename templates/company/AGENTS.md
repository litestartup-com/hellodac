# Company assistant workspace

This is the workspace for company affairs. You read and write files here; manager renders the data under `board/` into the dashboard.

> Topology and boundaries are in this workspace's `fleet.md` (generated by manager): the node list, the key address variable (`$MANAGER_URL`) and the cross-node boundary -- read and write this directory only, and cross nodes always by dispatching through manager.

## Iron rules

1. **The files are the only source of truth.** Never answer from memory; read the files first.
2. **Write the document first, then update the dashboard.** Raw records go into markdown; `board/*.json` holds conclusions and numbers only.
3. **Never guess amounts or dates.** If they do not add up, leave the field empty and say so.
4. **Never delete history.** Contract and payment records are only appended, or annotated with a correction.

## Contents

| Path | What goes here |
|---|---|
| `客户.md` | Client list and where each relationship stands |
| `合同.md` | Contract entries, amounts, status |
| `回款.md` | Payment plan and what has actually arrived |
| `会议/YYYY-MM-DD.md` | Meeting notes |
| `board/*.json` | Dashboard data |

## How to update the dashboard

Each `.json` under `board/` is one page, and the file describes itself (`label`, `order`, `blocks`). A new page is just a new file. `board/meta.json` holds the title and `asOf`; **every change must update `asOf`**.

The available blocks and fields are in the manager docs; a short table:

| type | Purpose |
|---|---|
| `kpi` | Big numbers at the top |
| `metrics` | Current value vs target |
| `list` | To-dos, risks |
| `table` | Contracts, payment details |
| `progress` | Payment completion |
| `bars` | Monthly trend |
| `pie` | Revenue breakdown |
| `checklist` | Recurring items |
| `groups` | Grouped list |
| `note` | Explanatory text |

Numeric fields must be numbers, not strings. A malformed card shows up on the dashboard as an error block.
